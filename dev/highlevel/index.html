High level interface

A simulation is described by a SimData, which lists its phases, and run by runTMS, which returns the Simulation it ends with. The High Level Interface page shows it at work.

Running a simulation

TensorMixedStates.runTMS — Function
runTMS(sim_data; max_time = Inf, checkpoint_interval = 0, threading = :dense, output = nothing)

run the simulation, see SimData, in a directory named after it, and return the Simulation it ends with. A checkpoint found in the directory is resumed from, if it was written by the same program, prog.jl in the directory, given the same arguments: copying an edited program there, or setting TMS_ACCEPT_PROGRAM=1, resumes it with that one. A file restart in the directory starts the simulation over, and cleanTMS removes the directory. A destination that is a file of the directory, as log or stamp, or a text file given two lists, is refused before the run starts.

  • max_time: seconds after which the run stops, writing a checkpoint
  • checkpoint_interval: seconds between two checkpoints, 0 for those of a stop only
  • threading: how the contractions are threaded, see set_threading: :dense, :blocks, :auto, chosen before each phase from the system of the state, or nothing, leaving the threading as it is
  • output: a stream to write everything to, stdout or devnull for instance, instead of a directory; nothing can then be resumed

The first three are overridden by the environment variables TMS_MAX_TIME, TMS_CHECKPOINT_INTERVAL and TMS_THREADING, TMS_MAX_TIME=3600 julia prog.jl for instance. The run also stops, writing a checkpoint, when the file stop appears in its directory, and on an interrupt. Runs may be nested or run on several threads: the outermost one sets the threading and the behaviour of Ctrl-C, which the last to end puts back, and an interrupt stops a nested run and the runs it is in, each resuming where it was. A nested run, as in an Update, is done again when the run it is in resumes, the same way with output = devnull and a seed only: in a directory of its own, it resumes its checkpoint or starts over, a seed drawn anew.

TensorMixedStates.SimData — Type
SimData(; name = "simulation", phases, options...)

the description of a simulation, which runTMS runs.

  • name: the name of the simulation, and of the directory its results are written to
  • phases: the phases, see TensorMixedStates.AbstractPhase, as a vector which may contain vectors to any depth, flattened
  • description: the text of the file description of the simulation (default "")
  • time_start: the time the simulation starts at (default 0)
  • final_measurements: the measurements made at the end, see output (default [])
  • format: the Printf format of the numbers written to text files (default "%.8g")
  • seed: the seed of the random number generator of the run, sim.rng, an integer of zero or above, drawn at random by default and written in the file stamp, so that a run can be made again

A measurement of a value that no phase provides is refused here, see TensorMixedStates.provided_values, and so is a state named by a name the run reserves, or twice in the on of a phase.

Examples

SimData(
    name = "ising",
    phases = [
        CreateState{Pure}(10, Qubit(), "Up"),
        GroundState(hamiltonian = -sum(Z(i) * Z(i + 1) for i in 1:9) - sum(X(i) for i in 1:10),
                    algo = Dmrg(nsweeps = 10), limits = Limits(maxdim = [10, 20, 50]),
                    final_measurements = "data" => [:energy, X, Z]),
    ],
)

TensorMixedStates.Simulation — Type
Simulation(sim, state[, time = sim.time]; values...)

the simulation runTMS runs and returns: a state, its time and its values, which the measurements read, sim.energy as c.energy. The form above gives sim another state, and possibly another time and other values, sharing its run. A value is a number, an array, a state, anything a phase leaves for the measurements and the phases after it; a checkpoint keeps it, so that it must not be changed in place.

  • sim.state, sim.time: the state and the time
  • sim.step: the steps the phase being run has done
  • sim.rng: the random number generator of the run, for every draw of a phase, see SimData
  • sim.name: the value name, a state named by CopyState for instance
  • sim.data: the rows gathered in each Data(name), under name, a table, see Data

Examples

sim = runTMS(sim_data)
rows = sim.data["magnetization"]

Phases

TensorMixedStates.AbstractPhase — Type
abstract type AbstractPhase

the supertype of the phases of a simulation. Every phase has these three fields:

  • name: the name of the phase, written in the log
  • time_start: the time the clock is set to when the phase starts (default nothing, keeping the time)
  • final_measurements: the measurements to make at the end of the phase, see output (default [])

A phase of one's own is a subtype with these fields and either of two interfaces, runTMS logging it, applying its time_start and making its final measurements:

  • a phase made of steps has methods of TensorMixedStates.prepare_phase, TensorMixedStates.step_count and TensorMixedStates.run_step; the run measures its field measurements, if it has one, every measurements_period steps (1 without that field), logs, commits and stops between two steps, and resumes it after the last step committed
  • a phase of a single call has a method of TensorMixedStates.run_phase, which calls TensorMixedStates.step_done wherever it can stop

A phase providing values to the measurements, as :energy, declares them with a method of TensorMixedStates.provided_values.

CreateState(; type, system, state, randomize, on, name, time_start, final_measurements)
CreateState(state::State; options...)

CreateState{Pure|Mixed}(n, site, state; options...)

a phase that creates the state of the simulation.

  • name, time_start, final_measurements: the fields of every phase, see TensorMixedStates.AbstractPhase

TensorMixedStates.Update — Type
Update(f; nsteps = 1, provides = [], measurements, measurements_period, name, time_start,
       final_measurements)

a phase that changes the simulation by the function f(c), which reads it as a measurement reads its context, c.state, c.time, c.step, c.rng, c.ground, and changes it by assignments:

  • c.state = st, c.time = t: the state and the time
  • c.x = v: a value of the simulation, measured and kept by the checkpoints, c.x = nothing removing it, which frees the memory of a state

The phase makes nsteps steps, the run measuring measurements every measurements_period steps, committing and stopping between two, as for Evolve, c.step being the steps done before. A stopped run resumes after the last step committed: f must draw with c.rng alone and act only through c, output(c, …) and log_message(c, …), what it changes elsewhere being neither kept nor done again. f works on a copy, which a failure leaves the simulation without.

  • provides: the names of the values f sets, which the measurements may then read, see TensorMixedStates.provided_values

Examples

Update(c -> c.ground = c.state; provides = [:ground])
Update(c -> c.ground = nothing)
Update(nsteps = 1000, provides = [:m], measurements = "kicks" => [Z(1), :m],
       measurements_period = 10) do c
    c.m, _, c.state = collapse(apply(kick, c.state), Z(1); rng = c.rng)
end

TensorMixedStates.Evolve — Type
Evolve(; evolver, duration, time_step | nsteps, algo = Tdvp(), limits, mpo_limits,
         measurements, measurements_period, on, name, time_start, final_measurements)

a phase of time evolution, see evolve.

  • name, time_start, final_measurements: the fields of every phase, see TensorMixedStates.AbstractPhase
  • evolver: -im * H for a Hamiltonian H, plus dissipators for a mixed state, or for an evolver depending on time a vector of terms [A, B => g], see evolve, the time being that of the simulation
  • duration: the duration of the evolution
  • time_step: the time step, adjusted to the nearest one dividing the duration into a whole number of steps, and taken with the sign of the duration (no step when that number is zero), or nsteps, the number of steps, one of the two being given
  • algo: the method, see EvolutionAlgorithm
  • limits: the limits of the state, see Limits
  • mpo_limits: the truncation of the MPO of the evolver, see PreMPO (default none)
  • measurements: the measurements made after every measurements_period steps (default 1), see output; the state the phase starts from is measured by the final measurements of the phase before
  • on: the name of the state the phase evolves, see CopyState, or a vector of names, the states of one system and one representation evolved together under the evolver, the time advancing once, for two time correlations for instance (default :state)

Examples

Evolve(evolver = -im * (Z(1) * Z(2) + Z(2) * Z(3)), duration = 2., time_step = 0.1,
       measurements = "data" => [X, Y, Z])

TensorMixedStates.Thermalize — Type
Thermalize(; hamiltonian, beta, beta_step | nsteps, algo = Tdvp(), limits, mpo_limits,
             measurements, measurements_period, on, name, time_start, final_measurements)

a phase that takes a mixed state $\rho$ to $e^{-\beta H/2} \rho \, e^{-\beta H/2}$, normalized to trace one, by an evolution in imaginary time, see thermalize: from "FullyMixed", the thermal state $e^{-\beta H}/Z$. The time does not move. It provides the values :beta, the inverse temperature reached, and :log_trace, the logarithm of the trace before normalization, see thermalize: 0 both for a beta shorter than half a step, which leaves the state normalized only.

  • name, time_start, final_measurements: the fields of every phase, see TensorMixedStates.AbstractPhase
  • hamiltonian: the Hamiltonian $H$
  • beta: the inverse temperature $\beta$
  • beta_step: its step, adjusted as the time step of Evolve, or nsteps, the number of steps, one of the two being given
  • algo: the method, see EvolutionAlgorithm
  • limits: the limits of the state, see Limits
  • mpo_limits: the truncation of the MPO of the Hamiltonian, see PreMPO (default none)
  • measurements: the measurements made after every measurements_period steps (default 1)
  • on: the name of the state the phase acts on, see CopyState (default :state)

Examples

Thermalize(hamiltonian = -sum(Z(i) * Z(i + 1) for i in 1:9) - sum(X(i) for i in 1:10),
           beta = 2., beta_step = 0.1, limits = Limits(maxdim = 64),
           measurements = "thermo" => [:beta, :log_trace, Z(5)])

Phases, methods, destinations and representations of one's own

How to use them is explained in Extending TMS.

TensorMixedStates.prepare_phase — Function
TensorMixedStates.prepare_phase(phase, sim)
TensorMixedStates.step_count(prepared)
TensorMixedStates.run_step(prepared, sim, k)

the interface of a phase made of steps: prepare_phase returns what the steps need, from the simulation as the phase starts, step_count the number of steps, and run_step makes step k, returning the simulation it leaves, see Simulation. On a resume, prepare_phase is given the state of the last step committed, with the time the phase started from, and the steps go on after it: what it prepares may depend on the system of the state, not on the state.

Examples

struct Kicks <: TensorMixedStates.AbstractPhase
    name::String
    time_start
    final_measurements
    nkicks::Int
    measurements
end

TensorMixedStates.prepare_phase(p::Kicks, _) = p
TensorMixedStates.step_count(p::Kicks) = p.nkicks
TensorMixedStates.run_step(::Kicks, sim, _) =
    Simulation(sim, apply(exp(-0.3im * X)(1), sim.state), sim.time + 0.1)

TensorMixedStates.run_phase — Function
TensorMixedStates.run_phase(phase, sim, done)

run phase on the simulation sim, its first done steps already done, and return the simulation it leaves. For a phase made of steps, it prepares the phase and runs the steps after done, ending each with step_done; a phase of a single call has a method of its own.

source
TensorMixedStates.step_done — Function
TensorMixedStates.step_done(sim, phase, k; last = false)

the end of step k of phase, the simulation sim holding what it reached: its measurements, when due, and its line in the log, then the commit of the step, a checkpoint when one is due, and the stop of the run when one is asked for. It returns the simulation, its value step set to k. A phase of a single call calls it wherever it can stop, a sweep of a search for instance: its run_phase(phase, sim, done) is then called with the steps already done. With last, the phase ends there, sim holding its result, which a resumed run takes without running the phase again: a search ending on its tolerance would otherwise go on.

TensorMixedStates.search — Function
search(algo, mpo, state, limits; sweep_done = nothing, krylov = Krylov(), done = 0,
       energy = nothing[, orthogonal_to, weight])

the lowest eigenvalue of mpo and its eigenvector, normalized, searched from state by the method algo, limits the limits of the sweeps, see Limits; sweep_done(sweep, energy, state, ends) is called at the end of each sweep, ends telling whether the search ends there, on its tolerance or its last sweep, with the state it returns, and krylov gives the defaults of the method of the caller. A search resumed after done sweeps takes the rest of the schedules, energy being that of the last sweep, which it returns when no sweep is left. Given orthogonal_to, pure states on the system of state, the search is that of the lowest eigenvector orthogonal to them, which dmrg makes by adding weight times their projectors to mpo, the energy being that of mpo alone. A single site, which dmrg does not take, is diagonalized whole, in one sweep, see lowest_on_site. A SearchAlgorithm of one's own adds a method, taking these two keywords only if it searches excited states.
